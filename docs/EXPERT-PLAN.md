# 날씨한눈 — 가상 전문가 3인 합동 기획 적용안
2026-10-25 | 대상 저장소: https://github.com/softm/weatherhannun | 서비스: https://weatherhannun.vercel.app/

> 이 회의는 서비스 기획자, 기상 전문가, 기상캐스터의 **역할을 시뮬레이션한 제품 기획 검토**입니다. 실제 전문가 3명이 회의하거나 외부 검수한 결과가 아닙니다.

## 북극성 지표

**사용자가 10초 안에** 현재 날씨 상태·앞으로 달라질 요소·오늘 적합한 행동을 판단할 수 있게 하되, **관측과 예보를 혼동하지 않는 것**을 최우선으로 한다.

## 1. 전문가 관점별 검토

| 역할 | 현행 기능에 대한 평가 | 요구사항 | 반론 및 타협 |
|---|---|---|---|
| 서비스 기획자 | 시간별·주간·대기질·농작업·지도 등 기능이 갖춰졌으나 첫 10초 가치가 약함 | 날씨 한 문장 브리핑과 맞춤 활동·관심 지역 | 과도한 개인화 설정 요구는 초기 사용 장벽이므로 기본 산책, 최대 5개 지역만 저장 |
| 기상 전문가 | Open-Meteo 현재 모델값을 실측처럼 해석할 위험; 데이터 모델 시각 혼동 가능 | 예보 유효시각/조회시각 구분, 근거 수치 노출, 결측·오류·캐시 표기 | 정확한 비 시작시각이나 기상특보를 보장하는 표현 금지. 공식 특보는 외부 원문 링크 |
| 기상캐스터 | 카드 숫자는 많지만 무슨 일이 바뀌는지 서술이 부족 | 상황→변화 시점→영향→권장 행동→불확실성, 10초/30초 모드 | 생성 AI로 없는 수치를 만들어내지 않고 규칙 기반으로 표현. 상세 모드와 '근거 보기' 제공 |

### 합의한 우선순위

- P0: 기상 모델 출처 및 신뢰도 표기, 전면 10초/30초 해설, 변화 이벤트 카드, 저장 캐시 경고
- P1: 관심 지역 최대 5곳, 관심 활동 저장, 추천 카드 → 상세 이동, 기존 날씨 기회창 유지
- P2: 국내 공식 실황·단기예보/특보·대기질 연동, 복수 지역 예보 비교, 서버 웹푸시
- P3: 관측값과 예보 스냅샷을 축적한 뒤 예보 정확도 평가 및 일정 서비스 연계

### 제외/보류

- 'AI 기상캐스터'라는 주장과 실존 기상캐스터 이미지/음성 사용: 실제 제작 주체·검증 근거 없음
- 위험하지 않다고 판정하는 공식 안전 점수: 공인 기준·현장정보 없음
- '실시간 관측', '실시간 특보 제공': 공식 관측/특보 API를 직접 연결하기 전에는 표기하지 않음
- 앱이 종료된 상태의 푸시 알림: 백엔드·push subscription/permission 서버 관리·지속 체크 인프라 미완성
- Open-Meteo 무료 엔드포인트로 광고 운영: 이용 조건 확인·적법한 소스 전환 전 불가

## 3. 핵심 UX 사용자 여정

1. 처음 방문: 기본 지역(서산)으로 모델 예보 로딩; 위치 권한 없이 바로 사용.
2. 브리핑: 10초 요약에서 변화 시점을 읽음 → 관심 있으면 30초 모드와 근거 펼침.
3. 활동 선택: 추천 TOP 3 클릭 → 활동 평가 화면으로 이동 → 최근 48시간 적합도와 이유 확인.
4. 지역 전환: 지역 검색 → 현재 지역 저장 ☆ 또는 빠른 지역 선택 → 모델을 재조회.
5. 탐색: 비/맑은 시간대 48시간·3일·7일 또는 지정 기간 → 시간별 예보·전국 날씨.
6. 데이터 신뢰: 화면의 모델 예보·관측 구분과 마지막 조회 시간 확인 → 필요 시 API 새로고침.

## 4. 기술 구조 및 화면 매핑

정적 프론트엔드(GitHub Pages 또는 Vercel)에서 HTTPS API를 호출한다.

- **app.js**: 데이터 조회, 상태 관리, 지역·활동, 기존 화면과 지도 렌더링.
- **forecast-insights.js**: 날씨 기회창, 농작업 기상 신호, 현재 앱 열림 상태의 알림 조건.
- **briefing-core.js**: DOM·네트워크 없는 순수 분석. 비/돌풍/기온/저온/고온 이벤트와 설명 근거 구성.
- **briefing-ui.js**: 10초·30초 토글, 근거표, 변화 카드, 사용자 관심 지역(로컬스토리지).
- **sw.js**: 오프라인 셸/PWA 캐싱. API 예보는 실측 데이터처럼 오프라인 지속 갱신하지 않음.

모델 데이터의 시각: \`weather.current.time\`은 예보 유효시각이지 API 요청 시각이나 공식 발표 시각이 아니다. \`fetchedAt\`은 클라이언트 조회 완료 시각이다. 모델 게시 시각이 API에 따로 제공되지 않으면 '모델 발표시각 확인 불가'로 처리한다.

## 6. 지켜야 할 표현

- '현재 기온' 단독보다는 **'현재 모델 예보 기온'** 또는 '현재 추정 기온'
- '3시에 비가 옵니다' 대신 **'3시 무렵 강수 가능성이 높아집니다'**
- '서리 발생' 대신 **'저온/서리 가능성 확인 필요'**
- '좋은 방제 날씨=살포 가능'처럼 결론 내리지 않기
- '갱신 완료'라는 말로 모델 자체 발표 시각과 API 조회 시각 혼동하지 않기
