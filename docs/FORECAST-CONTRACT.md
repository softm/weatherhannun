# 날씨한눈 — 해설 규칙 및 데이터 신뢰 계약

## 입력
현재: Open-Meteo \`current\` + \`hourly\` + \`daily\`.
보조: Open-Meteo air-quality \`current\` (모델 예측값).
예보 조회시각: 브라우저가 저장한 ISO 8601 UTC \`fetchedAt\`.
위치: 브라우저가 선택한 이름/위도/경도.

## 판단 임계값 (기획용 휴리스틱)

| 이벤트 | 구현 기준 | 사용자 노출 |
|---|---|---|
| 비 가능성 증가 | 향후 24시간 내 \`precipitation_probability >= 55%\` 또는 \`precipitation >= 0.3mm/h\` | 예상 **가능성** 및 증거 수치 |
| 돌풍/바람 | 24시간 내 \`wind_gusts_10m >= 40 km/h\` 또는 \`wind_speed_10m >= 30 km/h\` | 안전 유의 안내, 공식 특보 아님 |
| 저온 | 향후 36시간 내 \`temperature_2m <= 2°C\` | 서리 발생 단정하지 않음 |
| 고온 | 향후 24시간 내 \`temperature_2m >= 32°C\` | 체감·건강 위험 별도 추정하지 않음 |
| 기온 변동 | 현재 모델 기온과 약 6시간 후 기온 차가 절댓값 \`>= 6°C\` | 모델 기온 변동 예상 |
| 예보 캐시 오래됨 | 저장된 조회 시각이 현재보다 180분 초과 이전 | 오래된 예보 · 재조회 필요 |

이 기준은 공식 기상청 특보 발효 기준과 무관하며 의료/작업 안전 기준이 아닙니다.

## 형식
요약 10초: 현재 모델 상황 → 가장 가까운 주요 변화 또는 눈에 띄는 위험 기준 변화 없음.
상세 30초: 요약 → 최고/최저 기온 → 예보 시간순 최대 3건 변화 → 특보는 별도 확인.
근거 펼침: 현재 모델 기온, 향후 12시간 최고 강수확률, 24시간 최대 돌풍, 예보 유효시각, 가능 시 PM2.5 모델 추정.

숫자가 없으면 '정보 없음'으로 표기하고 보간 또는 조작해 작성하지 않는다.
예보 모델 자체의 발표 시각을 현재 API에서 별도로 확보하지 못하므로 유효시각과 혼용하지 않는다.

## 품질 테스트

\`\`\`bash
node --test tests/briefing-core.test.cjs
\`\`\`

기본 6가지: 안정적인 맑음, 비 가능성, 돌풍+저온, 데이터 없음, 오래된 캐시, 강수확률 결측.

## 지침
- 실제 관측소의 \`observedAt\`을 확보할 때만 '실측' 사용.
- \`fetchedAt\`은 API 데이터 읽기 시각이지 모델 발행시각이 아니다.
- 캐시로 화면을 그린 뒤 live 재조회 실패 시 새로고침 실패 표기 유지.
- 주간예보 모델 예측이 위험하지 않다고 해서 기상특보가 없다고 말하지 않는다.
- 대기질은 API 모델 예측이므로 국내 기준 예측 간이 분류/실제 측정소와 구분.
- 공식 API와 계약/licensing 검증 전에는 광고를 추가하지 않는다.
