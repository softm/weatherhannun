# 날씨한눈 지역관리 — 구현·검증 가이드
시행: 2026-10-26 · 저장소: https://github.com/softm/weatherhannun

## 사용자 흐름

| 상황 | 동작 | 기대 결과 |
|---|---|---|
| 첫 방문 / Geolocation permission prompt | 앱 자체 '현재 위치 사용하기 / 지역 직접 선택하기 / 나중에' 안내 | 사용자가 버튼을 눌러 브라우저 권한창을 호출하도록 함 |
| 첫 방문 / 이미 granted | 마지막 저장 지역이 없으면 GPS 자동 조회 | 현재 위치 모델 예보 표시 및 마지막 위치 저장 |
| 재진입 / GPS가 마지막 선택 방식이고 granted | 매 진입 GPS 재조회 | 장소 이동 반영. 응답 전에는 마지막 위치 정보 임시 사용 |
| 재진입 / 수동 지역 선택 | 자동 GPS 갱신 안 함 | 수동 선택 지역 보존 |
| permission denied | 안내 표시 + 지역검색 가능 | 반복 권한 팝업 금지. '현위치' 재시도는 사용자 버튼 클릭시에만 |
| 현위치 버튼 | 현재 위치 조회 (HTTPS 필요) | API 날씨 좌표 적용. 자동 URL 갱신에는 좌표 미포함 (GPS·수동 저장 지역 동일) |
| 직접 검색/빠른 선택 | 지역 즉시 전환 | 예보·시간별·농작업·지도 인사이트가 선택 지역 기준으로 업데이트 |
| 현재 지역 저장 | ★ 지역 저장 클릭 | 최대 10개. 다시 선택할 수 있는 칩 생성 |
| 저장한 지역 수정 | 수정 → 새 이름 저장 | 좌표는 동일, 표시 이름 변경 |
| 저장한 지역 삭제 | 삭제 → 실행취소 제공 | 선택 중인 지역 삭제 시 다음 저장 지역 또는 기본 지역으로 이동 |
| 이전 저장 데이터 있음 | localStorage V1 → V2 자동 이관 | 저장 지역 목록 중복 제거 |
| 공유 링크로 진입 | lat/lon/name 쿼리 적용 | 공유된 지역을 GPS 자동 조회로 덮어쓰지 않음 |
| 알림·기상·지도 | 기존 기능 유지 | 관련 지역의 날씨 표시 |

## 프런트엔드 구성

- \`location-core.js\`: 유효 좌표, 동일 지역 판정, 목록 중복 제거, 최대 10곳, 저장·이름 변경·삭제, 활성 지역 삭제 후 대체 선택.
- \`location-manager.js\`: 브라우저 Geolocation/Permissions API, 온보딩, 칩/관리 패널, 저장소 V1→V2 이관, 삭제 실행 취소.
- \`location-manager.css\`: 모바일 우선, Stitch 라이트/다크 토큰 재사용, 스크린리더·키보드 조작에 맞춘 기본 구조.
- \`app.js\`: 선택 지역 적용, 마지막 위치 유지, GPS 선택 시 URL에 좌표 자동 삽입 방지, 기존 날씨/지도 기능과 결합.
- \`briefing-ui.js\`: 기존 관심지역 구현 제거, 날씨 브리핑만 책임(중복 이벤트 방지).

### 브라우저 저장 키

| key | 목적 |
|---|---|
| \`weatherhannun_location\` | 최종 선택 지역/좌표/선택 방식(gps 또는 manual) |
| \`weatherhannun_places_v2\` | 10개 이하 저장 지역 및 별명 |
| \`weatherhannun_geo_intro_v1\` | 처음 안내를 완료했는지 |
| \`weatherhannun_favorite_locations_v1\` | 구버전 지역, 최초 이관 후 제거 |

## 개인정보·정밀도

- 기기 위치는 \`navigator.geolocation\`으로 이용자가 명시적으로 허용할 때 읽는다.
- Geolocation API 자체의 위치 조회는 장치 권한/플랫폼 정책에 따른다.
- 받은 좌표는 소수점 3자리(약 100m 수준)로 낮춘 뒤 날씨 조회·로컬 저장에 사용한다.
- 이용자가 링크 공유를 요청하기 전에는 GPS 및 수동 선택 지역 좌표가 브라우저 주소창에 자동 삽입되지 않는다.
- 지역 검색은 공개 Open-Meteo geocoding 서비스를 사용하며 이름 기반 조회를 지원한다.
- 현재위치 역지오코딩(정확한 도로명/동 표시)은 별도 인증 및 개인정보/쿼터 검토 전 구현하지 않는다. GPS 이름은 '내 현재 위치'로 표시하고 원하는 별명으로 저장할 수 있다.
- 사이트 접속 시 IP/기술정보, API 날씨 요청의 선택 좌표는 외부 서비스 제공자에게 전달될 수 있다.
- 권한 부여 자체는 브라우저/운영체제가 관리하며 사이트에서는 강제 변경/해제할 수 없다.

## 자동 테스트

\`\`\`sh
node --test tests/*.test.cjs
node --check app.js
node --check location-core.js
node --check location-manager.js
\`\`\`

\`tests/location-core.test.cjs\`에는 숫자 좌표 유효성, GPS 구분, 중복제거, 저장·전환, 이름 변경, 활성지역 삭제, 다른지역 삭제, 10곳 제한 등의 테스트가 있다.

## 운영 전 브라우저 회귀 점검

1. 새 시크릿 창/새 사이트 데이터: 온보딩 표시 → 현위치 버튼 누름 → 브라우저 권한창 → 허용 → 현재 위치 날씨.
2. 새 시크릿 창: 위치 거부 → 지역검색/지역 선택 계속 가능, 재진입 시 팝업 반복 없음.
3. 수동 지역 선택 후 새로고침: 선택 지역 보존, GPS로 자동 덮어쓰지 않음.
4. 현위치 선택 후 새로고침: 위치권한이 이미 허용되었다면 GPS 재조회.
5. 저장한 지역 2곳 이상 클릭하여 예보 변경, 각 지역 이름 수정/삭제 실행 취소.
6. 현재 선택 중인 지역 삭제: 다른 저장 지역 우선, 없으면 기본 지역. 목록 관리창 유지.
7. 기존 \`weatherhannun_favorite_locations_v1\` 값이 있는 브라우저에 배포: v2로 이관.
8. 데스크톱과 Android Chrome/WebView로 테스트; WebView는 네이티브 위치권한 승인 처리가 필요할 수 있음.
9. HTTPS/위치 권한 미지원 환경: 검색 경로가 항상 남아 있음.
10. PWA 서비스워커 업데이트 후 구버전 JS가 섞이지 않도록 최신 로딩 확인.

기상 특보, 공식 관측 API, 앱 종료 후 푸시 기능과는 독립적인 작업이며 이번 위치관리 변경으로 해당 기능을 완료했다고 표시하지 않는다.
