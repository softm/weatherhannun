# 날씨한눈 알림 제품·판정 기준

> 상태: 구현 기준 문서 · 2026-10-26
>
> 범위: 웹 알림 설정, 웹 전경 알림, Android 백그라운드 알림의 공통 제품 규칙

이 문서는 날씨한눈 알림이 **언제 켜지고, 무엇을 판단하며, 어떤 내용을 보내는지**를 정하는 제품 기준입니다. 임계값·알림 문구·설정 저장 형식·웹과 Android의 역할이 바뀌면 구현 및 테스트와 같은 변경에서 이 문서도 갱신합니다.

정확한 판정 함수의 실행 기준은 `alert-rules-core.js`, 웹 연결은 `forecast-insights.js`, Android 실행 세부사항은 [Android 알림 구현·운영 기준](https://github.com/softm/weatherhannun.android/blob/main/docs/WEATHER_ALERTS.md)에 있습니다.

## 1. 목표와 원칙

- 사용자가 매번 앱을 열지 않아도 **오늘 우산이 필요한지, 비가 없을 가능성이 높은지, 맑은 시간이 이어지는지, 저온·돌풍이 예상되는지**를 알 수 있게 합니다.
- 오전에는 오늘의 핵심 날씨를, 저녁에는 내일의 핵심 날씨를 한 번에 전달합니다.
- 같은 조건을 15분마다 반복 통지하지 않고, 조건이 새로 성립한 순간에만 알립니다.
- 모델 예보를 공식 관측·기상특보·서리 확정 정보처럼 표현하지 않습니다.
- 사용자가 저장하고 알림 권한을 허용하기 전에는 백그라운드 요청이나 알림을 시작하지 않습니다.

## 2. 웹과 Android의 역할

| 실행 환경 | 확인 시점 | 제공 기능 | 한계 |
| --- | --- | --- | --- |
| 일반 웹/PWA | 앱이 열려 있고 예보를 읽은 때 | 설정 저장, 현재 조건 표시, 브라우저 권한이 있을 때 가까운 조건 알림 | 브라우저를 닫으면 주기 확인과 오전·저녁 요약을 보장하지 않음 |
| Android 앱 | 네트워크가 있고 시스템이 작업을 실행한 때 | 약 15분 주기 조건 확인, 오전·저녁 요약, 앱이 닫힌 상태의 시스템 알림 | 절전·Doze·제조사 정책에 따라 실행 시각이 늦을 수 있음 |

웹의 상단 톱니바퀴 아이콘으로 여는 **설정 화면**이 알림 설정의 단일 진입점이며, Android WebView는 저장된 설정과 현재 선택 지역을 네이티브 브리지로 전달합니다. Android는 웹 프런트엔드를 복제하지 않고 백그라운드 실행과 시스템 알림만 담당합니다.

설정 화면의 알림 미리보기는 현재 불러온 모델 예보와 사용자가 고른 시각으로 즉시 갱신됩니다. 실제 Android 알림의 글꼴·여백·접힘 상태·액션 노출 개수는 Android 버전과 제조사 시스템 UI가 결정하므로 미리보기와 일부 다를 수 있습니다.

## 3. 활성화 흐름

```text
톱니바퀴 설정 → 지역 확인 → 조건·시간 선택 → “알림 조건 저장” → 알림 권한 허용
         → Android 설정 저장 → 즉시 1회 확인 + 약 15분 주기 확인
         → 조건 판정 → 방해금지·중복 확인 → 시스템 알림
```

- 새 사용자는 화면에서 오전 07:00, 저녁 19:00, 방해금지 22:00–06:00이 선택된 상태를 봅니다.
- 그러나 `알림 조건 저장`을 누르기 전에는 `configured=false`이므로 백그라운드 알림이 동작하지 않습니다.
- 저장 후에도 알림 권한이 없거나 모든 알림 항목이 꺼져 있거나 유효한 지역 좌표가 없으면 Android 주기 작업을 등록하지 않습니다.
- 예전 형식의 조건 알림 설정을 가진 사용자는 기존 선택을 보존하되, 오전·저녁 요약을 자동으로 추가하지 않습니다.
- 현재는 **현재 선택 지역 1곳**을 알림 대상으로 사용합니다. 사용자가 지역을 바꾸고 새 예보가 로드되면 Android에도 그 지역이 동기화됩니다.

## 5. 조건 알림 판정식

판정 대상은 현재 시각보다 90분 이상 오래되지 않은 시간별 모델 예보입니다. 시간 범위는 첫 번째 사용 가능한 현재 시각대 또는 미래 행부터 계산합니다.

### 5.1 12시간 내 비

향후 12개 시간별 행 중 처음으로 아래 하나를 만족하면 성립합니다.

- `강수확률 >= 사용자가 고른 비 임계값`
- 또는 `시간당 강수량 >= 1.0mm`

알림 제목은 `강수 가능성 높음`이며 첫 예상 시각과 강수확률 또는 시간당 강수량을 표시합니다. 강수량 신호를 유지하는 이유는 강수확률 값이 낮거나 비어 있어도 모델이 의미 있는 강수량을 제시하는 경우를 놓치지 않기 위해서입니다.

### 5.2 비 가능성 낮음

향후 6개 시간별 행이 모두 아래를 만족하고, 사용할 수 있는 행이 최소 3개일 때 성립합니다.

- 각 시간의 `강수확률 <= 100 - 비 안 올 가능성 기준`
- 각 시간의 `시간당 강수량 < 0.3mm`

예를 들어 80%를 선택하면 6시간 동안 각 시간의 강수확률이 모두 20% 이하이어야 합니다. 화면의 “안 올 가능성 80%”는 이해를 돕는 표현이며, 6시간 전체에 비가 오지 않을 결합확률을 통계적으로 계산한 값은 아닙니다.

강수확률과 시간당 강수량이 모두 있는 행만 “비 가능성 낮음” 근거로 사용합니다. 어느 한 행이라도 강수량이 비어 있으면 0mm로 바꾸지 않고 이 조건을 성립시키지 않습니다.

### 5.3 맑은 시간

향후 24시간 안에서 아래 조건을 모두 만족하는 시간별 행이 사용자가 고른 시간만큼 연속될 때 성립합니다.

- 낮 시간(`is_day=1`)
- WMO 날씨 코드 0–2(맑음 또는 대체로 맑음)
- 강수확률 20% 이하
- 시간당 강수량 0.1mm 미만

첫 연속 구간의 시작 시각을 알립니다. 이 값은 일조 관측이나 구름 한 점 없는 상태를 보장하지 않는 모델 기반 휴리스틱입니다.

날씨 코드·낮/밤·강수확률·시간당 강수량 중 하나라도 없는 행은 맑은 연속시간에 포함하지 않습니다. 결측 뒤에 새로운 완전한 연속 구간이 있으면 그 구간은 별도로 판정할 수 있습니다.

### 5.4 저온·서리 가능성

향후 48시간 안에 기온이 2°C 이하인 첫 시각이 있으면 성립합니다. 제목은 `저온·서리 가능성 확인`으로 표시합니다. 예보 기온만으로 지표면 서리를 확정할 수 없으므로 “서리 발생”이라고 단정하지 않습니다.

### 5.5 돌풍

향후 24시간 안에 10m 돌풍이 35km/h 이상인 첫 시각이 있으면 성립합니다. 제목은 `돌풍 위험 확인`으로 표시하며 공식 강풍특보와 구분합니다.

## 6. 오전·저녁 요약 내용

### 오늘 준비 요약

기본 07:00에 다음 내용을 최대한 제공합니다.

1. 제목에 지역, 현재 날씨 아이콘·기온·상태
2. 체감온도와 오늘 최고·최저기온
3. 앞으로 12시간 안의 첫 비 예상 시각과 강수확률 또는 최고 강수확률
4. 사용자의 비 임계값을 넘으면 `우산 챙겨요`, 아니면 현재 우산 판단
5. 비·돌풍·저온을 고려한 짧은 활동 준비 문구

`우산은 지금 불필요` 문구는 향후 12개 시간별 행 모두에 강수확률과 시간당 강수량이 있고 어느 행도 비 기준을 넘지 않을 때만 표시합니다. 12시간보다 짧거나 일부 값이 없으면 `강수 자료 일부 누락`으로 안내합니다. 내일 요약도 일 최고 강수확률과 강수량 합계가 모두 있을 때만 유리한 활동 문구를 표시하며, 둘 중 하나라도 없으면 확인을 유도합니다.

제목 예: `옥길동 · 🌤️ 17° · 대체로 맑음`

### 내일 계획 요약

기본 19:00에 다음 날의 내용을 제공합니다.

1. 제목에 지역, 내일 대표 날씨 아이콘, 최고·최저기온
2. 날짜·요일과 대표 날씨
3. 일 최고 강수확률과 예상 강수량 합계
4. 우산 또는 내일 활동 시간 확인 문구

제목 예: `옥길동 · 내일 🌧️ 18°/12°`

지정 시각은 정확한 알람 시각이 아니라 **알림 가능 시점의 시작**입니다. Android는 지정 시각부터 6시간 안에 실행되면 해당 요약을 일정일당 한 번 보냅니다. 6시간을 넘겨 실행되면 오래된 요약을 뒤늦게 보내지 않습니다.

## 7. 게시·중복·방해금지 정책

- Android 조건 알림은 조건별 활성 상태를 기기에 저장합니다. `거짓 → 참`으로 바뀔 때 한 번 알리고, 조건이 다시 거짓이 된 뒤 향후 재성립하면 다시 알립니다.
- 여러 조건이 한 번에 새로 성립하면 알림 하나의 여러 줄로 묶습니다.
- 같은 확인에서 오전·저녁 요약도 발송 대상이면 새 조건을 첫 번째 요약 알림에 합칩니다.
- 오전·저녁 요약은 종류별·일정일별 1회만 보냅니다.
- 방해금지 중에는 게시하지 않습니다. 조건이 방해금지 종료 후에도 계속 성립하면 종료 뒤 확인 시 알리고, 방해금지 중에 해소되면 지난 알림을 소급 발송하지 않습니다.
- 웹 전경 알림은 같은 브라우저 세션에서 조건·예상시각 조합을 중복 표시하지 않습니다. Android의 기기 저장 중복 방지와는 별개입니다.
- Android 알림 채널은 `아침·내일 날씨`와 `날씨 조건 변화`로 분리하여 사용자가 시스템 설정에서 종류별로 제어할 수 있습니다.
- 요약 알림은 날씨한눈 앱 아이콘과 `Open-Meteo 모델 예보` 출처를 표시하고, `시간별`, `활동 추천`, `알림 설정` 바로가기를 제공합니다. 조건 변화 알림은 `시간별`, `알림 설정` 바로가기를 제공합니다.
- 알림 본문은 잠금화면에서 시스템의 민감 콘텐츠 설정을 따르도록 `private` 가시성을 사용합니다. 사용자의 시스템 알림·잠금화면 설정을 우회하지 않습니다.

## 8. 시간·배터리·실패 처리

- Android `JobScheduler`의 최소 주기인 15분을 사용하고 네트워크 연결을 실행 조건으로 둡니다.
- 15분은 정확한 보장 시각이 아닙니다. Doze, 배터리 최적화, 제조사 백그라운드 제한, 네트워크 상태에 따라 늦어지거나 실행이 합쳐질 수 있습니다.
- 정확 알람 권한은 요구하지 않습니다. 날씨 예보 알림의 특성상 배터리 비용과 정확 시각 보장보다 지속 가능한 주기 확인을 우선합니다.
- 새 설정은 즉시 확인 작업도 한 번 요청합니다.
- 네트워크/API 실패 시 잘못된 알림을 만들지 않습니다. 즉시 확인 작업은 시스템 재시도를 요청하고, 주기 작업은 다음 실행에서 다시 확인합니다.

## 9. 설정 저장과 개인정보

- 웹 설정은 브라우저 `localStorage`에 저장합니다.
- Android 설정·조건 활성 상태·마지막 요약 일자는 앱 전용 `SharedPreferences`에 저장합니다.
- 전달하는 값은 설정 버전, 현재 지역 이름·위도·경도, 조건별 활성화·임계값, 요약 시각, 방해금지 시각입니다.
- 별도 날씨한눈 회원 서버에 설정이나 위치를 업로드하지 않습니다. Android 백그라운드 작업은 선택 좌표로 Open-Meteo Forecast API를 직접 호출합니다.
- 지역 이름은 최대 75자, 설정 JSON은 최대 12,000자로 제한하고 좌표·시간·임계값을 Android에서 다시 검증합니다.

## 10. 웹 → Android 설정 계약

브리지 이름은 `WeatherHannunAndroid`, 저장 메서드는 `saveAlertConfiguration(json)`입니다. 현재 계약 버전은 2입니다.

```json
{
  "version": 2,
  "configured": true,
  "location": { "name": "옥길동", "lat": 37.467, "lon": 126.818 },
  "rules": {
    "rain": true,
    "rainThreshold": 65,
    "dry": false,
    "dryThreshold": 80,
    "clear": false,
    "clearHours": 3,
    "frost": false,
    "wind": false
  },
  "schedules": {
    "morning": true,
    "morningTime": "07:00",
    "evening": true,
    "eveningTime": "19:00"
  },
  "quietHours": { "enabled": true, "start": "22:00", "end": "06:00" }
}
```

필드 삭제·이름 변경·의미 변경은 웹과 Android의 동시 호환성 검토 없이 하지 않습니다. 새 필드는 이전 Android가 무시해도 안전한 형태로 추가하고, 계약을 깨는 변경은 버전을 올린 뒤 마이그레이션을 제공합니다.

## 11. 데이터 해석과 사용자 문구

- 모든 판단은 Open-Meteo 모델 예보이며 실제 관측값이나 기상청 공식 특보가 아닙니다.
- `비 가능성 낮음`, `맑은 시간`, `저온·서리 가능성 확인`처럼 불확실성을 드러내는 표현을 사용합니다.
- 농작업·운전·야외 안전 결정을 알림 하나만으로 확정하도록 유도하지 않습니다.
- 공식 특보는 기상청 공식 페이지에서 별도로 확인하도록 안내합니다.
- 강수확률 결측 등 근거 값이 부족하면 추정해서 채우지 않고 해당 판정을 하지 않습니다.

## 12. 후속 기획 후보 — 아직 미구현

아래 항목은 현재 제공한다고 표현하지 않습니다. 데이터 신뢰성, 알림 피로도, 권한·배터리 비용을 검토한 뒤 우선순위를 정합니다.

| 우선순위 후보 | 내용 | 선행 조건 |
| --- | --- | --- |
| 높음 | 기상청 공식 특보 발생·해제 알림 | 안정적인 공식 API, 중복·지역 매핑, 출처·유효시각 표기 |
| 높음 | 출근·등교/퇴근 시간대 우산 알림 | 사용자 시간대 설정, 오전·저녁 요약과 중복 방지 |

## 13. 변경 체크리스트

알림을 수정할 때 다음을 한 변경 단위에서 확인합니다.

1. `docs/ALERTS.md`의 제품 의미와 임계값을 먼저 확인합니다.
2. 웹 `alert-rules-core.js`와 Android `WeatherAlertEvaluator.kt`의 판정이 같은지 확인합니다.
3. `forecast-insights.js`의 브리지 JSON과 Android `WeatherAlertConfig.kt`의 파서가 호환되는지 확인합니다.
4. 새 알림이 중복 방지, 방해금지, 권한 거부, 결측 데이터에서 안전한지 확인합니다.
5. 사용자 문구가 모델 예보를 실황·특보로 과장하지 않는지 확인합니다.
6. 웹 테스트 `node --test tests/*.test.cjs`를 실행합니다.
7. Android 정적 검증·lint·빌드와 실제 기기의 권한·절전·재부팅 동작을 확인합니다.
